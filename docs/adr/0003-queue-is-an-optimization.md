# ADR-0003：队列是优化，数据库才是事实来源

- 状态：已采纳
- 日期：2026-11-18

## 背景

生产环境里消息队列会挂、会丢、会重复投递。如果「run 是否会被执行」取决于消息是否送达，
那么一次 broker 抖动就会留下永远 queued 的任务，而且没人知道。

## 决策

- `runs` 表是任务的事实来源，`status='queued'` 就是待办；
- 队列只负责「尽快唤醒 worker」，支持三种后端：`memory`（单进程测试）、`db`（无 Redis 也能跑）、
  `redis`（生产多 worker）；
- worker 用**原子 claim**（`UPDATE ... WHERE status='queued'`）保证重复消息不会重复执行；
- worker 空闲时做一次 **DB 兜底扫描**：队列丢消息只影响延迟，不影响正确性；
- 进程重启时把 `running` 复位为 `queued`（崩溃留下的假状态）。

## 后果

- 好处：Redis 故障时系统降级而不是丢任务；本地开发不需要任何 broker。
- 代价：DB 上多了一次轮询查询（可接受）；水平扩展时要注意 claim 的竞争（已用条件更新解决）。
