# ADR-0001：规则引擎与模型引擎并存，而不是「只上大模型」

- 状态：已采纳
- 日期：2026-11-18
- 决策者：平台负责人

## 背景

评审质量只有两个来源：确定性规则（正则、路径约束、静态检查）和大模型语义理解。
团队常见做法是直接接大模型，但落地时会遇到三个问题：

1. 成本不可控：每个 PR 都过模型，全量开启后账单不可预测；
2. 结果不可复现：同一份代码两次评审结论不同，无法做回归测试；
3. CI 里不可用：模型抖动会让流水线随机变红。

## 决策

平台同时保留两条引擎，通过 `OCR_MODE` 切换，下游（去重、投递、指标）完全一致：

- `rules`：确定性规则层，零 token、可离线、结果可复现，作为**基线与门禁**；
- `cli`：上游 `open-code-review` + 真实模型，负责语义级问题。

bench 分两层：规则层要求 F1 不降（满分基线），模型层用**录制回放**做回归，
阈值更宽（允许 3% 波动），因为它本来就是概率性的。

## 后果

- 好处：CI 可以在没有 API key 的情况下跑完整回归；成本可控；面试/演示时能对比两条引擎。
- 代价：规则层需要维护（我们用 `fixtures` 正负样例做回归）；两套引擎的 severity 词表需要对齐
  （上游 `critical` → 平台 `blocker`），这层映射有专门的契约测试。
