# 架构决策记录（ADR）

按时间顺序记录「为什么这样做」，而不是「做了什么」。代码会变，决策的约束不该丢。

| 编号 | 决策 | 一句话 |
|---|---|---|
| [0001](0001-two-tier-engines.md) | 规则引擎与模型引擎并存 | 规则层做基线/门禁，模型层做语义，CI 无 key 也能回归 |
| [0002](0002-idempotency-vs-dedupe.md) | 幂等与去重拆开 | webhook 幂等、run 唯一、评论去重是三个不同的问题 |
| [0003](0003-queue-is-an-optimization.md) | 队列是优化，DB 是事实来源 | broker 挂了只影响延迟，不丢任务 |

## 写 ADR 的标准

1. 有真实的取舍（两个方案都能work，选了一个）；
2. 写清楚后果，包括代价；
3. 能独立读懂，不依赖当时的口头讨论。
